# Variables d'environnement SC2_*

Le runtime (`recomp-sc2/runtime`, `recomp-sc2/src/main.c`) et l'hôte Android (`android/jni`) se règlent par des
variables `SC2_*`. Sur Android, on les pose dans `sc2.env` (une ligne `NOM=VALEUR`, `#` en tête = commentaire) :
d'abord `/sdcard/SC2Partout/sc2.env`, que le lanceur de l'APK réécrit, puis `sc2.env` du stockage externe de l'app,
lu après et qui l'emporte. L'activité complète ensuite quelques défauts (indiqués « Android : » ci-dessous) et impose
`SC2_ROOT`. Au banc Mac (et Linux), c'est l'environnement du processus (`env NOM=VALEUR … recomp-sc2`, cf.
`scripts/banc-mac.sh`) ; l'app Mac lira plus tard son propre `sc2.env`. La liste ci-dessous est celle des littéraux
`"SC2_…"` du code : `scripts/variables-sc2.sh verifier` (appelé par `scripts/verifier.sh`) échoue dès qu'une
variable lue par le code manque ici. Les variables propres aux scripts (`SC2_EXTRACTION`, `SC2_DISQUE_MIN_GO`,
`SC2_APK_*`…) sont documentées en tête de chaque script.

Lecture des tableaux : « défaut » = comportement quand la variable est absente. Le rôle commence par la cible :
*commun* (tous les hôtes), *Android*, *Mac*, *banc* (runs de mesure ou de régression), *diagnostic* (outil
d'enquête, sans effet sur le jeu quand il est absent). « lue dans » = premier site de lecture (le même que
`scripts/variables-sc2.sh squelette`) ; `scripts/variables-sc2.sh ou` les donne tous. Sauf mention, une variable
booléenne s'active par `1` et se coupe par `0`, et n'est lue qu'une fois par run.

## Escarmouche contre l'IA (V4.10)

Partie mêlée hors ligne contre l'IA du jeu (`recomp-sc2/runtime/sc2_escarmouche.c`) : au démarrage, avant tout code du
jeu, la carte choisie est copiée depuis le cache Battle.net pré-rempli de l'installation
(`Mods/Liberty.SC2Mod/Base.SC2Data`, 63 cartes) vers `C:\Users\sc2\Documents\StarCraft II\Maps\Escarmouche\` du `C:\`
émulé, son `MapInfo` et son `MapScript.galaxy` sont réécrits (joueurs Computer, races, `PlayerSetDifficulty`), puis le
lanceur simulé la lance en mode 2 à la place de TStory01 (un `-run` de `SC2_ARGS` l'emporte). Journal `[ESCARMOUCHE]` ;
en cas d'échec (carte introuvable ou ambiguë, cache illisible, carte refusée), `[ESCARMOUCHE] ÉCHEC …` et le jeu démarre
normalement. Posées par le lanceur Android (section « Escarmouche contre l'IA ») ; banc : `scripts/banc-escarmouche.sh`
et `docs/BANC-MAC.md` (« Escarmouche »). Les valeurs ignorent la casse, les accents et les tirets.

## Mac

V3 (22/10, lot M0) : toutes les variables de la vague 3, documentées d'avance (v3-critique.md §3.1, greffe 6) ; la
colonne « lue dans » donne le lot qui la lira tant qu'aucun code ne la lit (`scripts/variables-sc2.sh verifier` ne fait
qu'avertir pour celles-là). Sur macOS, l'exécutable `recomp-sc2` est à la fois le banc et l'app (`docs/BANC-MAC.md`,
« Binaire unique ») : `SC2_FENETRE` choisit le mode. L'app lit aussi `<SC2_MAC_SUPPORT>/sc2.env` (lot M3), sans jamais
écraser une variable déjà posée dans l'environnement du processus : un essai impose les siennes.

Variables existantes que l'hôte Mac lit aussi, avec leur sens sur Mac : `SC2_SWAPCHAIN` (banc : `1` = surface sans
écran à la taille de `SC2_ECRAN`, présentateur de M5 ; app : défaut `1`), `SC2_ECRAN` (`auto` résolu par l'hôte d'après
la fenêtre, lot M7), `SC2_FPS_PERIODE` (ligne `[FPS]` de l'hôte, swapchain seulement), `SC2_TRACE_PRESENT` (aussi au
banc Mac), `SC2_PAUSE` (réduction, Cmd+H, veille ; une fenêtre seulement occultée ne met pas en pause), `SC2_PRESENT`
(défaut `mailbox` sur Mac, lot M5), `SC2_BARRE` (absente : jamais sur Mac, lot M5), `SC2_VK_LIB` (posée par l'hôte vers
le MoltenVK du paquet s'il existe et qu'elle est absente, lot M3), `SC2_VARIABLES` (semis de `Variables.txt`, V1.5).
